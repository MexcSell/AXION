# Evolution Step 1 Implementation Plan: containerised live site + Guard

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AXION runs live as blue/green Docker slots behind a front proxy on :5190, and a Guard on the host takes a commit live only after
build, tests, boot and smoke pass, and switches back automatically when the new version fails after the switch.

**Architecture:** Each slot is one container (one image per commit) running today's two processes: the API on 127.0.0.1:5191 *inside* the
container and `vite preview` on :4190 serving `web/dist` and proxying `/api`. An nginx front container routes :5190 to the active slot.
Slots reach the host's PostgreSQL through the mounted Unix socket as OS user `axion` (peer auth, no cluster change). Singleton background
work runs only in the slot holding a PostgreSQL advisory lock. The Guard is a dependency-free Node 24 TypeScript CLI under `evolve/guard`,
with a pure core (tested with fakes) and thin Docker/git/HTTP adapters, installed to `/srv/axion-evolve` and run by Claude Code.

**Tech Stack:** Node 24 (host, native type stripping), `node:test` for `evolve/`, vitest for `server/`, Docker 29, `nginx:1.27-alpine`,
`postgres:16-alpine` (throwaway test DBs only), Playwright 1.56 image for browser checks.

**Spec:** `web/docs/evolve/2026-11-26-autonomous-evolution-design.md` (approved 2026-11-26). Read §6, §7.1, §7.3, §8 step 1, §13.

## Global Constraints

- Never touch other apps: other PostgreSQL databases, other Docker containers/networks/images, k3s, nginx on :80. Every Docker object is named `axion-*`.
- No change to `/etc/postgresql/**` and no PostgreSQL restart. Slots connect only via `/var/run/postgresql` as OS user `axion`.
- The API keeps binding 127.0.0.1 (`server/src/main.ts` rule unchanged); only `vite preview` listens on 0.0.0.0, inside the container.
- No secret in an image, in git or in a log: `.env*`, `server/data/`, `backups/` are excluded by `.dockerignore`; the live secrets file is `/srv/axion-evolve/secrets/live.env`, mode 600, owner root.
- Live slots use Claude 2 (chat) only, through the egress proxy; allowlist starts as `api.anthropic.com:443`. Claude 1 is not used in step 1.
- No new SQL migration in step 1; migrations 0001–0065 unchanged. Migrations run at start only when `AXION_MIGRATE_ON_START` is not `0`.
- Server test count may not drop below the baseline measured in Task 3 (record it in `evolve/baseline.json`).
- Work on local branch `evolve-step1`; one commit per task; no push to GitHub.
- Steps that change the host (Tasks 7–9) are run by Claude Code with the owner's step 1 approval; Task 9 (cutover) additionally waits for the owner to be told the time.

## Review Focus

1. **A browser with a live event stream open during a switch** → it reconnects to the new slot and events resume (owner sees the connection badge recover, no reload needed). Test in Task 8.
2. **A chat message posted while slots are switching** → answered exactly once (old slot's in-flight answer may be dropped; the new leader's sweep answers it once). Tests in Tasks 1 and 8.
3. **The Guard is killed after the switch, before the watch ends** → `axion-guard status` shows the unfinished deploy; `axion-guard rollback` returns to the previous slot and is safe to run twice. Tests in Tasks 5 and 6.
4. **Host reboot or Docker restart** → front and the active slot come back by themselves pointing at the same version; the standby slot stays stopped. Test in Task 8.
5. **Two deploys started at once** → the second is refused with "a deploy is already running" and changes nothing. Tests in Tasks 5 and 6.
