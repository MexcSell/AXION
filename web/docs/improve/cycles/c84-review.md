1 (major, wording) Split validity. A true random item split gives pilot|total hypergeometric, and that is what is drawn, so the distribution is right IF the draw were independent randomness. It is instead a fixed hash of the four counts (judge-calibration.ts splitRng/splitCalibration): pilot is a deterministic function of the total table. Independence of pilot and holdout is therefore heuristic (a fixed pseudo-random function), not guaranteed, and the report's "independent of the holdout apart from the fixed total counts" overclaims. The sim does exercise the real function, which is the actual evidence. Also manipulable: re-labelling or adding one item re-rolls the split; and a caller choosing counts can search for a favourable one. Fix: state it as heuristic in the header and report; optionally seed from item ids/order or add a secret salt, or note the re-roll risk as a backlog item.
