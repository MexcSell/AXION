# c41 re-review (bb5e5a2 to 1c05f53)

Verdict: NOT CLEAR (two Important findings, both small). Everything else in the fix round holds.

## Important

1. Hidden characters pass the charset (server/src/agents/playbooks.ts:41-46, `BAD_CHARS`). The allow-list takes all of `\p{L}` and `\p{M}`, which includes default-ignorable code points. Probed: U+034F (combining grapheme joiner), U+115F/U+1160/U+3164/U+FFA0 (Hangul fillers, category Lo), U+17B4/U+17B5, U+180B-180D/180F, U+FE00-FE0F (variation selectors), U+E0100-E01EF are all accepted (268 code points in total). The error text and the report promise "no hidden characters". Effect: skill names and lesson text can look identical yet differ (two "Deploy" skills that are different names, so different versions chains), and invisible payloads fit inside accepted text. Zero-width (U+200B/C/D), bidi (U+202E), tag characters, NEL, U+2028/9 and backtick-via-NFC (U+1FEF) are correctly refused. Fix: add `\p{Default_Ignorable_Code_Point}` to the refusal (and ideally require a base character before an `\p{M}`).
2. Source `note` and typed source ids still reach members (server/src/agents/playbooks.ts:`shapeSource`). Ruling 4 says notes and source ids are admin-only. `shapeSource` hides only `mission` and `task` sources; for `review`, `failure_tag` and `note` it returns `{...s, verified}` with the proposer's free-text `note` and id intact, in accepted items, diffs, versions and skills. The test pins this on purpose for the id (`REV-9`) but never checks a `note` on an unverified source. A proposer writing "customer Acme complained" on a `review` source exposes it to every member. Fix: drop `note` for non-admins on every kind (keep it for admin and for the proposer's own candidate or skill), and decide explicitly whether typed ids also become "source hidden".

## Minor

1. Event payloads (`playbook.lessonProposed`, `skill.proposed`, audience all) carry ids of other people's private drafts and the agent id. Ids only, 128 bits, and the routes 404, so this is existence and timing only. No text, no notes in any event or error message (checked every `emit` and every `ApiError`).
2. checkSources (playbooks.ts:`checkSources`) gives different 404 messages: "No such task." (unknown id) versus "No such mission, or it is not shared with you." (a task of an unseen mission). That tells a member a task id exists. Use one message.
3. A lesson restored by a later rollback stays `superseded` with `withdrawn_in_version` set (the status is never moved back, and the trigger forbids it), so the candidate list says "withdrawn" for an item that is in the playbook again. Display only; the playbook is right. Worth a line in the help or a "restored in vN" field later.
4. Trigger (migration 0033 `lesson_candidates_guard`): for an accepted row it pins status, decided_*, notes and accepted_in_version, and the earlier block pins all content columns, so nothing else can change. The value of `withdrawn_in_version` is free (any non-null int). Only the server writes it, so Minor.
5. After NFKC, 22 allowed code points become forbidden text (U+00BC-BE, U+2150-215F vulgar fractions become `1⁄4`, U+013F/0140 `L·`, and similar). The allow-list runs after NFC only, not NFKC, which is consistent with storage (nothing NFKC-normalises on the way in). A consumer that NFKC-folds later could see U+2044 or a middle dot. Harmless as quoted data; mention in the help or reject `\p{No}` and `\p{Nl}`.
6. `proposeLesson` is exported and takes raw text (only `squash`, no charset or NFC). Today it is called only by the route (after the schema) and by one test. A future agent-proposal caller would bypass the charset. Apply the same `plain` check inside `proposeLesson`.
