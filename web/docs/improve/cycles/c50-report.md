## Concerns
- The `admin: true` flag in the registry is the author's statement; the 403 loop proves a flagged route is gated, but nothing proves an unflagged route is not admin-only (the happy call runs as the right role either way). A static scan of `requireAdmin` per route would close it.
- The event-emit scan is a regex over `type: 'a.b'` literals. A future emit through a computed type would escape the "emitted but undeclared" check (the coverage run still validates it when produced, as an unknown type).
- Arrays that are empty in the flow cannot validate their elements; the flow re-reads lists after creating data for the routes that matter (tasks, mentoring, version proposals, site grants, failure tags).
- Tasks, approvals and notifications are seeded through SQL or service helpers (no public create routes); `instance.stateChanged` and `approval.consumed` have no HTTP producer, so they are driven through the service functions, as c15 and the approval tests do.

## Fix round (review c50-review.md, PASS-WITH-FIXES)
Each item was done test-first; RED output was captured before the fix or by temporarily breaking the guard, then reverted.

1. **Open mission and agent validators (F1).** `openObj<T>` now takes `{ [K in KnownKeys<T>]-?: V<T[K]> }` (KnownKeys strips the index signature), so tsc rejects a missing, extra or mistyped named key; only the declared index stays open at runtime. `staffing`, `phases[]` and `prePause` got real DTOs (`StaffingDto`, `PhaseDto` in `shared/contracts/src/api.ts`) and `metrics` is a typed `Record<string, number>` on `AgentStoredDto`; `avatar` stays an open dictionary (declared `Record<string, unknown>`). RED: removing `rowVersion` from the mission validator gives `TS2741: Property 'rowVersion' is missing in type ...` (before, tsc accepted it).
2. **Recursive non-vacuity (F2).** Validators carry `meta` (shape, item, inner, alts), and `walk.ts` walks every body next to its validator tree. For every object node of the richest real body of every route and of every event type it adds an extra key, drops each key and nulls each key, and the validator must reject unless the contract allows it (the child validator accepts absence or null). More than 2000 mutations run. RED: disabling the extra-key check in `obj()` fails the test. A second test requires every object array to have been non-empty and every nullable field non-null in some call of its route (and event type); the first run listed 230 findings, now each is either populated or on `exercised.ts` with a reason.
