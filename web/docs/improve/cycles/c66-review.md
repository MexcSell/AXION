### S1 (should-fix): the writability scan has holes that are not stated in the report
Evidence: `server/test/contracts/writability.ts` line `const re = new RegExp(\`\b(?:insert\s+into|update|delete\s+from)\s+(${tables})\b\`, 'gi')`. I ran this regex over probes: it matches `update  tasks`, `INSERT INTO\n tasks` and misses (0 matches) `insert into public.task_reviews`, `update "tasks"`, `update only tasks`, `merge into tasks`, `truncate tasks`, `copy tasks from stdin`, `insert into ${tbl}`.
- Current `server/src` has none of those forms (grep for `${`/quoted/schema-qualified table positions is empty), so today nothing escapes. The report says "table level, not column level" but not "literal SQL only".
- Bigger hole: a write through a helper has no SQL in the caller. `instances/backfill.ts` calls `insertDelegation` and `insertInstance` (line 37, 63) and `missions/staffing-sim.ts` calls `insertInstance`/`joinMission`, and `agents/playbooks.ts` is reached by c63's `failures/patterns.ts` via `proposeLesson`. The scan attributes the write to `instances/service.ts` only, so a new file that calls `insertDelegation(..., kind:'verifies')` with an agent identity passes with no declaration. `taskBackfill` declares only tasks.status and tasks.owner and `staffingSim` does not declare agent_instances or mission_delegations.edge, although both reach them through helpers.
- Triggers and cascades: I scanned migrations; no trigger function writes an input table. FK cascades exist (`on delete cascade` from missions to tasks, task_reviews, failure_tags, delegations ...). Only `DELETE /missions/:id` and `clearDemo` (both human or system) reach them, so the classification is right, but it is by argument, not by test. No dynamic SQL found in `server/src`. `server/scripts` or other dirs outside `server/src` are not scanned.
- Table level: over-flags (see S2) and under-flags (a new column on `tasks` written by an agent site is invisible). Suggested fix: add to the report and to the file header the limits "literal `insert into|update|delete from <bare table>` only, helper calls and non-`src` code not seen", and add a second scan: any file that imports `insertDelegation`, `insertInstance`, `joinMission`, `setInstanceState`, `proposeLesson`, `createTag`, `recordReview`, `createBrief`, `requestApproval` must be a declared caller. Widen the regex to allow `(?:public\.)?"?`, `only`, `merge into`, `truncate`.
- "Agent can reach it" is hand-typed per site (`kinds`), not derived from code. Spot-checked 6 sites against the code, all correct for today: `recordReview` (route passes `{kind:'user'}` default, reviewer kind agent only by parameter; `tasks/reviews.ts:146`), `createTag` (route hardcodes `taggedByKind:'user'`, `failures/routes.ts:34`), `joinMission` (emits `actorKind:'agent'`, `instances/service.ts:51`), `requestApproval` (`actorKind:'agent'`, `approvals/service.ts:70`), `ledger-routes` (human only; no agent literal besides the CHECK), `staffing-sim` (system timer). The test "every field with an agent site flags a one-input row" (report threshold b) is close to a tautology: it re-derives the hand-typed kinds.

### S2 (should-fix): `verified_success_rate`, `completed_unverified`, `kpi.success.api` are over-flagged through `mission_delegations.edge`, and the report's reasoning is wrong

At minimum correct the report concern 3 and add a gate string to `instanceService` ("writes only delegated edges; the verified rule reads verifies edges").
