# Lessons

One line per cycle: what it taught and whether PROCESS.md changed.

- C1 (A1): a new writer of shared state makes old read-then-lock paths race. Whenever a feature adds a writer, list the existing writers of the same table and give them all one lock-then-read path. PROCESS step 4 now asks for this.
- C2 (B1): the live API runs from the working tree, so restart it only when the tree is clean (between cycles), never while another implementer has uncommitted work. Process step 11 updated.
- C3 (C1): until agents execute, real missions never produce finished tasks, so measurement features can be proven only in server tests. They add little visible value now. Favour governance flows people can use today (structure changes, version proposals) and code health. Measurement is limited to the scaffolding already built. Backlog order changed.
- Lanes (parallel worktrees): symlinked node_modules sit outside Vite's fs.allow, so fonts return 403 in a lane's dev server and .gitignore's 'node_modules/' misses symlinks. Lane setup needs a Vite fs.allow override that is never committed, plus 'node_modules' without the slash in .gitignore (done). The same api-stage6 agent-edit check flaked in c01, c02 and c04, so H4 should go next.
- Lanes: 'git stash' is shared by every worktree of a repo. A lane's 'stash pop' applied another lane's stash (w3 and w5, undone by w3). Rule: lanes never use git stash; LANES.md updated.
- c07: lanes must never load pages from live ports, even read-only, and heavy host load (14 lanes) makes page.reload timeouts look like regressions. Verify on the integration tree at merge time and keep the 3-slot gate for every lane (w2–w5 started before it existed).
- Gate sizing (19:12Z): heavy runs are mostly browser-bound (Postgres stayed under 20 connections), so 3 slots made a queue of about 30 runs with 15-minute verify-alls. Raised to 6 by atomic file replace (never edit a running bash script in place). Size gates by measured resource use, not a guess.
- c15: lane implementers can still dispatch subagents despite the rule (one no-op happened). Keep the rule in every brief; the reviewer checks reports for it.
- Integrator starvation (19:35Z): the integrator, the critical path, queued behind about 15 lane runs for over an hour. heavy.sh now has a reserved slot 0 for HEAVY_PRIORITY=1 (integrator only). Lesson: in any shared queue, give the merge path its own capacity.
- Shared Vite cache (19:45Z): symlinking web/node_modules gave every lane one .vite deps cache. Each tree's Vite rewrote it for the others, causing 504 Outdated Optimize Dep errors and probably the recurring page.reload timeouts blamed on load. Each lane now has its own node_modules dir of per-package symlinks, and so its own .vite. Lesson: sharing a dependency folder also shares its caches; share packages, not the folder.
- Connection budget: a semaphore on processes doesn't bound DB connections when each process opens a pool per worker. Protect shared infrastructure with a hard cap at the resource itself (role connection limit), not only with a job gate.
- Gates must be honest: verify-all's exit code ignored sub-script FAILs for the whole loop, so 'green' meant 'didn't crash'. A gate is only as good as its weakest exit code; test the gate itself by forcing a failure.
- Workers can all die at once from outside causes (here: sign-in). Everything that matters must live in git and the loop files, not in agent memory: the integration queue, rulings, and every lane's brief. Lanes should commit work-in-progress often.
- c25: converting a fixed sleep before an ABSENCE assertion to an animation-settle wait makes the check pass before the data arrives. An absence check must wait for a positive signal first. A cleanup cycle can quietly weaken tests, so review hygiene changes as strictly as features.

## Phase 2, Wave 1–2 (2026-11-22)
- **New constraints break code the lane never runs.** Twice, a NOT NULL or insert guard broke `scale-bench.ts`: c31 (audit chain) and the c31+c35 combination. Every brief that adds a constraint now says "grep scripts and fixtures for raw inserts". The controller also checks the interaction across branches when two lanes touch the same table.
- **Clocks.** Three reviews (c32, c35, c36) found app-clock vs DB-clock comparisons. Rule: expiry, revoke and consume compare in SQL with `now()`.
- **Append-only needs all four guards.** UPDATE, DELETE, TRUNCATE, and the purge_demo exception, plus a test that clearDemo still works. c32, c35 and c36 each missed one.
- **Fail closed beats enumerating.** c36's look-alike lists missed whole scripts. Refusing every IDN, with an explicit later path (P4a), was safer and simpler.
- **"Self" rules need a real second person.** Producer ≠ verifier and decider ≠ requester only bite if the data has distinct humans. With a single admin and agent-raised requests, they are dormant (P3b, Q9). Make the gap visible rather than claiming the rule.
- **Licences of research artefacts.** The MAST paper is CC BY-NC-ND. Keep names and ids with attribution, and write our own descriptions.

### Phase 2, integration (batches 7–9)
- **Locks are named globally even when tables aren't.** Every test file gets its own schema in one database, but an advisory-lock key is a number shared by the whole database. Two "random" 500s at about 5 s (batch 5f in agents.test, and c31's sign-in audit) had the same cause: one test held a key on purpose, and other schemas' writes hit `lock_timeout`. The fix was to scope every key by `current_schema()` through one helper, plus a guard test that bans raw `pg_advisory` calls. **Rule:** any shared name (lock keys, LISTEN channels, temp files, ports) must be derived from the isolation unit. A flake that disappears with 1 worker is shared state, not "transient".
- **A file watcher can silently stop.** The live 5190 Vite served an old `contracts/index.ts`, `touch` didn't help, and 6/10 verify-all steps failed while the build passed. When the build is green but the dev server isn't, restart the dev server before blaming the code.
- **A performance fix can expose a latent race (c44).** Removing a needless page re-render made c26's older-page anchor drift 150–436 px, because the re-render had been hiding a race by changing commit timing. Bisect by reverting one file at a time, then fix the race, not the optimisation.
- **Numbers taken at different loads aren't comparable.** c44's first result (NOT MET at load 11–19) became a PASS at load below 8. Measure base and candidate interleaved at the same load and with the same flags, and print the load next to every number.
