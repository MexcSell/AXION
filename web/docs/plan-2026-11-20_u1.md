# Plan: UI update 2026-11-20_u1

Source: `update/2026-11-20_u1.md`. This is a frontend prototype only: DEMO data, persisted in the browser, no backend.

Owner decisions taken before starting:
- **Rail:** the top section shows only Missions, Notifications and Settings. Overview, Results & Versions,
  System Operations and Help are *hidden* from the rail by default. They stay reachable through search, links and
  deep URLs, and Settings › Navigation can show them again. The bottom section holds plug-ins (Job Search).
- **"Merge face-to-face aspects into one"** means one chat system. Every conversation uses the same chat component and one
  conversation store: direct agent chat, the GM/Admin chat in the top bar, mission threads and Job Search agent chat.

My interpretations (flagged in PROGRESS.md):
- "Model Louder agent" means the **Model Loader** agent. It picks the right model for each agent and replaces the old
  Finance role, since funds are gone.
- "Ilgam" (일감) means a job or work site. "Bid" means a freelance proposal: Job Search finds jobs, and agents tailor
  the profile and submit bids.

## Steps (each step: build → typecheck → screenshot check → next)

1. **Remove and re-route.** Delete Usage & Budgets, Knowledge, Governance, Evolution Lab and Browser Studio (pages, data,
   dialogs, help, CSS). Users moves into Settings, and Agents and Models move into System Operations. Old URLs redirect.
   The TopBar loop points away from removed pages.
2. **Rail split and navigation settings.** Top shows Missions, Notifications and Settings, plus hidden extras. Bottom shows plug-ins.
   `config/plugins.ts` is the plug-in registry. Settings › Navigation shows or hides every rail item and has
   "Create a plug-in through a mission".
3. **Funds removed everywhere.** Drop budget, cost, money and limits from types, data, the mission wizard, header, dialogs, agents,
   models and help. Delete the `budget` approval kind. Finance role becomes Model Loader.
4. **Users and sign-in (demo).** A `store/auth.ts` holds accounts (avatar, name, password hash, role, status, devices).
   - The Register/Connect screen asks for name and password, then Connect.
   - The **first account becomes admin** automatically.
   - Later accounts and new devices wait for admin approval and connect automatically once approved, even across browser tabs.
   - Settings › Users covers my profile (avatar, name, password change, my devices) and admin approval of users and devices.
   - Verification scripts get a seeded admin session.
5. **Missions.**
   - The add-mission composer takes text plus files (image, audio, video, doc, pdf, txt) and nothing else.
   - The GM appoints the general executor first, and the executor then recruits agents (staged, animated).
   - A mission belongs to the user who added it. Users see their own and shared missions; admins see all. A share toggle controls this.
   - Each agent logs per-mission activity: tokens, active time, CPU, RAM and current action.
   - Agents work several missions at once. Each mission instance merges back into the original agent on an interval.
6. **One chat system.** `features/chat/` holds a shared thread, bubble, composer and channel store. Mission Messenger uses it.
   It is also used by the direct agent chat (individual tasks), the top-bar dock left of the account button
   (General Manager plus Site Administrator) and the Job Search agent chat.
7. **System Operations.** Adds Agents (with Directory, Development, Lineage & Knowledge and Live Instances sub-views),
   Models (Manager, Routing by Model Loader, ...) and VMs. Old Browser Hosts merges into VMs.
   - Lineage: Developer → Mobile Developer / Web Developer, and Homepage Controller → per-site Autopilot agents.
   - Each agent's knowledge is split into what it keeps and what it shares upward to its parent.
8. **Notifications.** Top and bottom boards are foldable. A **News** tab shows a feed from users, plus URLs and content added
   by search and research agents, with an Add news dialog. New-user and new-device requests appear for admins.
9. **Job Search plug-in** (`/plugins/job-search`, replaces Browser Studio).
   - **Investigate** tab: job sites on the left (add URL), live preview of the selected site with investigation steps
     in the middle, and mobilized agents with chat on the right.
   - **Jobs** tab: researched jobs with bid status and details.
   - **Profile** tab: documents and free text. Each bid shows the profile the agents tailored for that job.
10. **Search everything.** The palette indexes actions and commands, every page and tab (hidden ones too), missions you can see,
    agents, models, VMs, users, plug-ins, job sites, jobs, news, notifications, settings and help entries.
11. **Clean-up and verification.**
    - Help keys, dialog registry and scripts (crawl routes, flows, fit-check, dialog smoke) get updated.
    - Build, then run verify-all, fit-check and a screenshot review in dark and light.
    - PROGRESS.md, KIT.md and README get updated.

## Refinements after review (applied while executing)
- Order: Step 1 deletes only Usage, Knowledge, Governance and Evolution. `/agents` and `/models` stay live until step 7 mounts them
  in Operations. Browser Studio is deleted in step 9, when Job Search replaces it. Users is deleted in step 4.
- Delete page by page, because the defs, help and CSS files are shared by area. Run tsc, check-dialogs and check-help after each page.
  Approval links move to Notifications › Pending.
- Data store version is bumped, with a migration that drops budget and cost, adds owner and shared, and maps the finance id.
- Auth: accounts live in localStorage and the session in sessionStorage, one per tab. A `storage` listener handles auto-connect. Device approval
  uses a simulated second device. Fixture members are seeded after the first real account. The theme hook is lifted above the gate.
  Scripts seed an admin session through one helper.
- Mission visibility: one `useVisibleMissions()` selector used everywhere. `/missions/:id` is guarded. Fixtures include other users' missions.
- `/` lands on `/missions`.
- Nested tabs: Operations uses `?tab=`, embedded pages use `?sub=`, and Agents Directory keeps `?view=`. Departments, Assignments, Policies and Proposals stay.
  The growth, stage and generation display stays.
- Agent uniqueness is per duty, with `parentId` lineage. Job Search site agents share ids with the lineage tree.
- `addMission` derives its title from the content. Lead = the executor the GM appoints. Agents join progressively.
  `Attachment.kind` adds audio, video and doc.
- Funds grep, extended: costEff, spend, price, usd, Wallet, Coins, DollarSign, fund, limit, forecast. Monthly model limits go; token usage stays.
- Crawl and flows run after steps 1, 4, 6 and 7. Scripts are updated in the step that breaks them.
